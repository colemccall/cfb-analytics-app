# data/

Every file here is **generated by the pipeline** (`cfb-analytics-pipeline/`) and committed so GitHub Pages can serve
it. Do not edit by hand: the next export overwrites it. The app reads these files through `js/dataLoader.js` only.
How they are made: `cfb-analytics-pipeline/docs/DATA_FLOW.md`.

| Files | One per | Written by | Read by |
|---|---|---|---|
| `players_{season}.json`, `rosters_{season}.json` | season (2008–2026) | script 12 | Players, rosters, player card. 2026 rows carry the live rating (`live_rating`, `live_status`, `live_through_week`). |
| `teams.json`, `team_ratings.json`, `team_history.json` | — | 12 | Team select, team page, rankings. |
| `schedules_{season}.json`, `power_games_{season}.json`, `team_stats_{season}.json`, `ratings_by_position_{season}.json`, `similar_players_{season}.json` | season | 12 | Schedules, the power table, team stats, position boards, similar players. |
| `live_2026.json` | the season being played | script 17 | Earned-to-date ratings: the Season screen and every 2026 live number. |
| `weekly_teams_{season}.json`, `weekly_players_{season}.json` | replayed / live season | script 17b | Week-by-week panels, Rankings by week. |
| `gamelog_{season}_{team_id}.json` | team (2026) | 12 `--game-logs` | The player card's Games tab. A team with no rostered players has none (Idaho). |
| `recruiting_{year}.json`, `transfers_{season}.json`, `player_transfers.json` | year | 18, 12 | Recruiting and the portal. |
| `trajectory*.json`, `reliability.json`, `draft_validation.json`, `team_performance.json`, `recruiting_roi.json`, `coaching_impact.json` | — | 12–15, validators | Research and methods pages. `draft_validation.json` is not read by any page. |
| `cards/` | player shard | 12 `--cards` | Player cards (1,024 shards). |
| `research/index.json` | — | 12 | The Published Findings list. It is `[]`: the publishing path is not wired (root `CLAUDE.md` §6). |
| `manifest.json` | — | 12 | Which seasons exist and which are projected; `js/config.js` must agree (`tests/test_frontend_config.py`). |
| `headshots.json`, `backdrops.json`, `api_availability.json` | — | 19, 20, 09 | Images and the API coverage table. |

**Size.** About 600 MB in about 1,320 files. GitHub Pages publishes up to 1 GB, so large additions need a reason.
The weekly files cost about 4 MB per season.

**The rules the exporter keeps**, tested in `cfb-analytics-pipeline/tests/test_export_contract.py`: valid JSON (no
`NaN`), one season per per-season file, missing values as `null` (rendered "—"), never 0.
